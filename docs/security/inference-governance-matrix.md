## Enforced protocol distinctions

- Compatible chat intentionally does not release speculative output before the complete content-policy verdict. This prevents a detector match split across chunks or final lookbehind from leaking. It is a protocol-level latency tradeoff, not a weaker control.
- Provider HTTP bodies are still read incrementally through a bounded `ReadableStream`; response cancellation, byte ceilings, hard deadlines, and upstream backpressure remain active while the verdict is produced.
- Stateless OpenAI-compatible requests cannot resume a durable interactive policy approval. An approval-required decision therefore fails closed with a stable public error.
- Compatible embeddings accept only reviewed catalog models and bound dimensions, total values, finite numbers, response bytes, and safe-integer usage fields before returning or metering.

## Required release evidence

- Compatibility governance, provider execution, secret egress, output parsing, usage, and API-runtime circuit/fallback tests pass.
- Provider normalization and embedding bound tests pass.
- Core and provider typechecks pass.
- The architecture ratchet and public-error registry pass with no new bypass or oversized production file.
