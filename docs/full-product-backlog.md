# Romeo Full-Product Completion Backlog

This index converts the remaining PRD priorities into an implementation backlog. The detailed phase work is split by track so individual files stay reviewable and maintainable.

The target is a product that remains Docker Compose compatible for local and self-hosted installs, while being Kubernetes enterprise scale ready. Kubernetes Postgres should support both CloudNativePG-managed Postgres and externally hosted Postgres through the same application contract: `DATABASE_URL`, migration job, pgvector readiness, backup/restore, and DR drill flows.

## Backlog Rules

- The Phase 19 greenfield baseline is locked; future schema changes require forward-only migrations with upgrade tests and rollback or mitigation notes.
- Every phase must preserve Docker Compose and Kubernetes compatibility.
- Every persistent feature must define repository contract, Postgres implementation, authorization, OpenAPI, TypeScript SDK, CLI or worker path where relevant, tests, and docs.
- Worker and connector execution must stay out-of-process or explicitly bounded. No arbitrary user code, shell pipelines, or Open WebUI-style in-process pipelines.
- Secrets must be passed by managed references or deployment secret injection, never copied into logs, jobs, audits, sync summaries, or API responses.
- Audit, usage, jobs, and webhook payloads must store metadata only unless a specific product requirement and retention policy explicitly allows richer content.
- Enterprise behavior must be tested with seeded-login disabled, production secrets present, durable storage configured, and readiness passing.
- Each phase must include rollback and disaster-recovery expectations.

Full-product enterprise completion uses the `pnpm ga:checklist -- --profile full-product-enterprise --strict` evidence profile. That profile keeps the default GA gates and turns on every opt-in enterprise/live gate together, including Qdrant live/DR, hosted CI governance, KEDA, browser automation, target identity, data connectors, tool dispatch, voice, notifications, analytics authorization, vector route comparison, data-rights retention, billing operations, audit integrity, tenant purge, support bundle, target resilience drills, and Postgres operations. Individual `--require-*` flags remain available for narrower deployment claims, but they are not enough for the full-product completion claim tracked by this backlog.

## Cross-Phase Acceptance Gates

Every phase must pass these gates before it can be called done:

- API contract is documented in OpenAPI and covered by SDK tests.
- Service-layer authorization tests include negative cases.
- Audit metadata is reviewed for redaction.
- Jobs and usage metadata are reviewed for redaction.
- Readiness behavior is defined for unsafe production config.
- Compose compatibility is documented or tested.
- Kubernetes compatibility is documented or tested.
- Migration impact is reviewed against the post-lock forward-migration policy.
- Backup/restore impact is documented.
- Security review records egress, secret, and payload behavior.
- No large catch-all files are introduced; new code is split by domain and responsibility.
